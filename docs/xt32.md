# XT32 preview, recording and export

Select **Hesai PandarXT-32** in the LiDAR page before capture. This requires
the XT32-capable Agent and matching Host SDK ABI13. Standard XT32 is supported;
XT32M2X is not. Switching models requires stopped capture.

Before first use, install the actual LiDAR calibration CSV on RK at
`/userdata/prism/hesai/xt32.csv` (or Agent `PRISM_XT32_CORRECTION_FILE`). Configure
the LiDAR to unicast to the RK IP, UDP 2368 by default. Viewer network settings
configure RK reception, not the LiDAR's IP/destination/RPM/return/clock mode.
Start/stop only controls reception, not the motor. Agent failures (including
missing calibration) are shown rather than silently selecting nominal angles.

Preview, dataset recording, local playback, validation and ROS1/ROS2 export
recognize model 3. Web-recorded XT32 datasets use the same portable layout.
New manifests use `cartesian-mm-chunk-v3-with-point-time`: models 1/2 keep their
16-byte points, model 3 stores 24 bytes per point:

| Byte offset | Field |
| --- | --- |
| 0/4/8 | signed int32 XYZ in mm |
| 12/13 | uint8 reflectivity/tag |
| 14 | uint16 ring (0–31) |
| 16 | **signed** int32 ns offset from packet tail |
| 20/21 | uint8 return ID / raw vendor reserved byte |
| 22 | uint16 reserved zero |

The existing `lidar.tum` columns are unchanged. Batch timestamp is the mapped
packet tail; `timestamp_raw` is raw tail ns, not the first point. No timing
interpolation is applied to XT32. Dual returns retain their own timestamps.
Unsynchronized batches can preview but are excluded from synchronized datasets.

Export uses standard PointCloud2, `frame_id=hesai_xt32`, 100 ms time windows.
XT32 fields: XYZ float32 (0/4/8), intensity uint8 (12), tag uint8 (13), ring
uint16 (14), offset_time uint32 ns (16), return_id uint8 (20), vendor_reserved
uint8 (21), point_step=24. Time = header + offset_time; offsets are normalized
from the first point, including valid negative source offsets and dual returns.
This is time-window aggregation, not azimuth-aligned revolution segmentation.
There is no deskew. Vendor-reserved values are not a confidence estimate.

Old Livox datasets remain readable and preserve their existing PointCloud2
layout. Old Viewers cannot read XT32 datasets; upgrade the Viewer and SDK together.
