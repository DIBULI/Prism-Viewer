# Prism Viewer 1.2.0 用户操作手册

[返回 Viewer 首页](../../README.md) · [版本功能汇总](../release-notes/v1.2.0.md)

适用于 Viewer/SDK/Agent 1.2.0 与配套 Sensor Board 0.4.27。以“设备信息”显示的实际版本为准。
本手册使用 Markdown 维护；界面文字可切换中文或 English。

## 1. 快速开始

1. 给设备稳定供电，用可靠的 USB 3 数据线直连电脑。
2. 启动 Viewer，刷新并选择设备。只有一台设备时可以自动打开，但**打开不会自动校时**。
3. 在“设备信息”核对版本、USB 速率和实际配备的相机/IMU。单 IMU 产品只显示 IMU0，不算故障。
4. 在空闲状态设置相机帧率、JPEG 质量，并选择是否启用雷达及其型号。
5. 点击“开始采集”，检查实际有数据的各路计数和速率。
6. 需要保存时另行开始录制。结束时依次停止录制、停止采集、关闭设备，再退出 Viewer。

保持数据集完整移动，不只复制索引文件。升级期间保持电源稳定，不拔线或强制退出。

## 2. 连接与设备信息

- 同时连接多台设备时，用序列号选择目标。
- USB 设备只能由一个采集客户端占用；连接失败先关闭其他 Viewer/SDK 程序。
- Linux 首次使用需安装 USB 权限规则，见[安装说明](../../README.md#linux-usb-permissions)。
- “设备信息”用于查看设备版本、传感器在线情况、传输状态和错误。
- 单路缺数据会显示告警和缺失相机编号，其余正常数据流继续；真实 USB 断连仍会结束会话。
- 黄条可能表示尚未读取、等待就绪或尚未验证，不应直接解释为硬件故障。查看具体文字和日志。

## 3. 时间同步

设备公共时间域可以是启动相对时间或已建立的 UTC。内部对齐不等于外部授时成功。

- 当前配套固件仅输出内部对齐后的板载 IMU。启动或重新对齐时可短暂无 IMU 输出，其他流不因此停止。
- 没有 GNSS 锁定也能建立内部对齐；不能因此把启动相对时间当成 Unix UTC。
- 需要电脑校时时，先停止全部采集，显式点击“校准设备时间”，等待成功或明确错误。
- 外部 GNSS 正在授时时，不使用手动校时替换它；按钮不可用时先检查采集和授时状态。
- 校时失败不应靠反复启停或伪造时间绕过。记录错误并检查设备状态。
- 数据集保留时间域；录制中出现不允许的时间倒退或时间域变化会报告完整性错误。

相机时间戳代表曝光触发开始，不是曝光中心或电脑收到图像的时间。板载 IMU 使用测量时间；
传感器滤波和曝光中心造成的算法时延，不等同于设备时钟未对齐。

## 4. 相机预览与配置

### 预览

各相机分别显示图像、计数、速率、曝光及可用元数据。只判断实际安装且有数据的通道。
单击图像可放大；缩放、平移、适应窗口只影响显示，不改变原始数据。
预览可能跳过过时画面，因此显示刷新率不等于设备触发率。

### 帧率与 JPEG

停止采集后刷新设置，再保存帧率（1–30 FPS）与 JPEG 质量（1–99）。
这些设备配置在下一次采集准备时应用。高质量通常增加数据量，应按实际带宽和写盘能力验证。

### 曝光和模拟增益

曝光、增益、上下限和目标亮度支持采集中调整，属于运行时设置。
默认目标亮度为 35；允许的曝光上限同时受用户限制和当前帧率限制，以界面回读值为准。

- 独立自动模式：每路自行控制亮度。
- 手动模式：在公共限制范围内设置该路曝光和模拟增益。
- 统一自动曝光：有效相机使用共同曝光时间，模拟增益保持独立。
- 当前配套固件按有效相机反馈调节；缺一路不会持续卡住其他相机曝光/增益。
- 自动增益等待生效反馈，最多每秒调整五次，接近目标时减小步长。
- 高光保护采用约 20% 饱和像素容忍策略，不代表保证任意场景都不过曝。

暗场提高增益会增加噪声，延长曝光会增加运动模糊。优先补光，按场景设定上下限；
修改后观察实际曝光、增益和图像，不只看输入框。

## 5. 板载 IMU

IMU 页显示实际存在的通道、测量值、速率与时间状态。显示单位切换不改变数据集的 SI 单位。
每路样本计数独立，不直接用 IMU0/IMU1 的样本编号判定同时采样。

临时无数据与设备断连不同。若长期无数据，检查检测状态及日志；不要把旧样本重复当作新样本。
当前固件在未对齐时不输出，不在之后补发这段历史数据。

## 6. LiDAR

1. 空闲时选择 MID360、MID360S 或 XT32，并勾选随采集启用。
2. 配置正确的设备网口和雷达地址，避免地址冲突，执行连接测试。
3. 开始采集后确认点数持续增长。网络可达不等于已经收到点云。
4. 点大小、旋转、缩放、俯视和重置视角只改变渲染，不修改记录数据。

显示、网络和待机/唤醒分别位于 LiDAR 子页。
**停止采集不等于停止扫描**；待机/唤醒是独立操作，要求全部采集停止。
唤醒不会自动开始采集。操作超时应刷新状态，不把未确认当成功。

详见[待机/唤醒](../lidar-power.md)、[XT32](../xt32.md)和[逐点通道](../livox-line.md)。

## 7. GNSS / RTK

RTK 页中分别查看 GNSS、CORS/模块状态以及天空图/轨迹。

- GNSS 与接收机 RTK 结果分开展示，区分 SINGLE、FLOAT、FIX 等解类型。
- 卫星天空图和卫星表用于查看收到的观测；可见卫星数量不等于实际 RTK 参与卫星数量。
- 精度使用接收机提供的有效指标，不把 HDOP 或状态文字当成置信度百分比。
- 定位失效或数据过期时不把旧位置当作新解。RUNNING 也不等于已经 FLOAT/FIX。
- 配置 CORS 和启动定位是不同操作；账号保存、应用及连接成功也分别确认。
- 连接 CORS 前确认服务端和账号，并明确允许发送设备实时 GGA 位置。
- 不把账号密码写入日志或对外报告；按界面选择是否在本机记住密码。

具体流程、数据新鲜度和 GNSS/RTK 轨迹区别见[可视化说明](../gnss-visualization.md)。

## 8. 网络与 Wi-Fi

网络页读取热点状态、SSID、地址及开机启用状态，可启用/禁用设备热点并保存选择。
切换热点可能中断经该热点连接的网页或 SSH；USB 会话不依赖它。
只在可信网络使用设备服务。网页用户名为 admin，访问密码向客服询问。

## 9. 录制数据集

开始采集后，选择完整数据集或仅 IMU 等所需模式，再开始录制。
仅录制真实收到的数据，不补缺失相机或重复旧数据。

- 预留足够磁盘空间，录制中观察写入计数和告警。
- 单路缺数据不会停止其他采集，但缺少所选数据会使数据集被标记为不完整。
- 时间戳错误、磁盘写入失败属于独立完整性错误；不能仅因可以预览就认为录制有效。
- 点击停止录制后等待文件关闭和完成状态更新，再停止采集。
- 容器文件与索引必须放在一起；保留整个数据集目录，不单独改名或移动分块文件。

格式和具体字段见[数据集格式](../dataset-format.md)。

## 10. 回放、验证与导出

本地数据集页将 Camera、IMU、LiDAR 分开显示，共用播放时间轴；切换标签不重新开始回放。
打开数据集后可逐帧查看、拖动时间轴、选择回放速度，并检查元数据。

先执行数据集验证，查看文件、容器范围、时间连续性及数据缺失报告。
有效但有警告不代表适用于所有算法；无效或未完成的数据应保留原文件排查。

通过“导出 ROS Bag”在电脑上生成 ROS1 .bag 或 ROS2 SQLite3 数据集。
转换不会将启动相对时间伪装为 UTC，也不会自动去畸变或补齐缺失传感器。
详见[ROS bag 导出](../rosbag-export.md)。

## 11. 下载 RK 上的数据

通过当前 USB 连接进入“本地数据集 → 从 RK 导出”，刷新后选择数据集、目标和输出类型。
不走设备 Web 的 80 端口，也不需要输入网页密码。
下载前停止设备采集和升级。SDK 下载原始格式，Viewer 可随后在电脑上转换 bag。

保持原始文件完整；下载失败或取消会留下临时结果，不自动当作完成文件。
详见[RK 数据集下载](../rk-datasets.md)。

## 12. 系统升级

1. 停止录制及全部采集，接好稳定电源。
2. 选择可信的联合系统升级 ZIP，核对目标设备和组件版本，明确确认后执行。
3. 等待校验、传输和完成反馈；不要断电、拔 USB、关闭应用或让电脑休眠。
4. 按提示重新连接，刷新版本与状态，再短时验证采集。

联合包不同于 TF 镜像 ZIP，不能混用。Viewer 会跳过相同版本的 Sensor Board；
若发布说明要求替换同版本固件，应按该包说明执行机内的显式强制更新。
仅看到联合升级完成，不能证明被跳过的固件已替换。失败后保留日志，先查状态再决定重试。

## 13. 日志、语言与故障排查

- 日志可复制当前打开、采集、同步、录制与升级错误；报告问题时附版本、时间及操作步骤，去掉凭据。
- 空闲且设备关闭后再切换语言，按界面提示重新打开 Viewer。
- 无设备/权限错误：检查 USB 数据线、直连端口、其他占用进程及 Linux USB 权限。
- 单路黑屏或无 IMU：看缺路状态和计数，其他流可继续；不要仅因缺一路就反复重启设备。
- 无点云：检查雷达型号、供电、地址、待机状态和数据计数。
- 录制/导出失败：检查空间、数据集完整性和时间域，保留原目录。
- 升级失败：保持供电，保存日志，核对当前状态；不要在状态未知时连续重复刷写。

退出顺序始终为：停止录制 → 停止采集 → 关闭设备 → 退出程序。
